## Summary

As of 2026-11-08, the packaged app has passed the native package gate and the interactive acceptance matrix, including a live VoiceOver pass, on **macOS 27.2 arm64 only**. **macOS 14** and **Intel x86_64** have not been exercised. They remain open in [issue #1](https://github.com/Takazudo/zudo-stl-fix/issues/1), and the overall work is tracked in epic [#22](https://github.com/Takazudo/zudo-stl-fix/issues/22).

:::warning
A validated mesh is not proof of printability, fit, wall thickness, or strength. None of the results below mean "print ready".
:::

## Latest: 2026-11-08, macOS 27.2 arm64

The package was built from `fb20af9`, which combines the CLI alias safety fix (#27) with the collision-performance, contrast and focus fixes (#28). Toolchain: Xcode 27.2, Swift 6.4.2, CPython 3.12.14.

| Check | Result |
|---|---|
| `make test-engine` / `test-worker` | 17 and 54 passed |
| `make verify-fixtures` / `verify-hashes` | 17/17 and 13/13 passed |
| `PYTHON=python3.12 bash scripts/build-macos.sh` | Passed. 65 Swift tests, the real-worker test **passed and was not skipped**, signatures and the relocated helper smoke passed |
| Eleven originals | Two defective rails **Repair ready** with tiny-triangle warnings; five **No repair needed**; four **Checked — review needed** with below-Z warnings; no redundant copies |
| Saving into a folder with 10,000 colliding names | Finished in about 0.2 s (about 4 minutes on 2026-11-07). The exhausted row stayed retryable, the other row saved, and no staging files were left |
| Saved STLs rechecked independently | Watertight, one shell, complete scan, zero invalid pairs, bounds unchanged |
| Contrast of warning and failure text | At least 5.4:1 in light and dark appearance, with icons in addition to color |
| Keyboard focus on **Advanced** | Fully visible at the minimum window size, collapsed and expanded |
| Live VoiceOver | Drop group, Choose Files, file names, states, warnings, row actions, batch save, the Details text and Done are announced. Advanced is announced as a disclosure triangle with its expanded or collapsed state |

The archive is ad-hoc signed, not notarized, and not released. The full record is `verification/implementation/macos-arm64-2026-11-08.md` in the repository.

## Earlier arm64 records

On 2026-11-07, two builds passed the package gate and broad Finder/UI acceptance: Finder drag-and-drop, the open panel, per-file and batch save, read-only destinations, cancellation, quit, stale-workspace cleanup, light and dark appearance, and resizing. That run found and fixed missing failure reasons and the **Choose Files…** accessible name.

## Still pending

Interactive checks that were performed on the relocated app: launch from a path with spaces and Japanese characters; opening all 11 originals via `open -a`; one window; the nine healthy originals show **No repair needed** and both defective rails show **Repair ready** with the tiny-triangle warning visible; Save controls enabled only for those two; the quit-with-unsaved-repairs confirmation; stale workspace cleanup after a forced kill; fixture hashes unchanged.

### Defects found and fixed (2026-10-16)

Running the real app found two defects that unit tests missed: every file failed because a `/private` path prefix was stripped before it reached the worker, and every Finder-opened file created a new window. Both are fixed and covered by tests.

### Pending as of 2026-10-16 (later resolved on arm64 except macOS 14 and x86_64)

These were not exercised, because the session had no Accessibility permission to drive the UI:

- Finder drag-and-drop onto the window.
- The save panel, per-file and batch, and independent re-verification of saved STLs.
- Read-only destinations and name collisions in the UI.
- Active and queued cancellation in the UI.
- Details and JSON report export, and Reveal in Finder.
- Keyboard access, VoiceOver, light appearance, and resizing.
- The macOS 14 floor, which was not runtime-tested; only the host OS was exercised.
- x86_64.

Saving, collision, permission, and cancellation logic is covered by Swift tests, not by UI interaction. The full checklist is in `docs/ACCEPTANCE.md`.
