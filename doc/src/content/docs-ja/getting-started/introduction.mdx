## できること

zudo-stl-fix は macOS ネイティブのアプリ（SwiftUI/AppKit）で、**STLファイルをドロップ → 自動チェックと保守的な修復 → Save Fixed Files** というひとつのワークフローに沿って動作します。

- Finder からドロップしたファイルや、**Choose Files…** で選んだバイナリ形式・ASCII形式のSTLファイルを受け付けます。
- 見た目が閉じたメッシュだからといって有効だとは見なさず、交差する三角形ペアのスキャンも含めて各ファイルをチェックします。
- エンジンが保守的に修正できる問題だけを修復し、実際に書き出すバイト列そのものを再チェックします。
- 検証済みのコピーを `<original-stem>-fixed.stl` という名前で保存します。修復が不要なファイルについてはコピーを作りません。

処理はすべて Mac 上で行われます。アカウントもアップロードもなく、パッケージ化されたアプリは Python のインストールを必要としません。ジオメトリエンジンは、アプリに同梱された別のヘルパープロセスとして動作します。

## 行わないこと

- 拡大縮小、回転、移動、スムージング、ボクセル化、任意の穴埋め、近接する壁の溶接は行いません。
- モデルが造形可能か、寸法が合うか、十分な強度があるかは判定しません。詳しくは[検証は造形可能性の証明ではない](../concepts/validation-is-not-printability.mdx)を参照してください。
- 3Dプレビュー、メッシュエディタ、スライサー連携はありません。
- フォルダ、アーカイブ、リモートURL、STL以外のファイルは処理しません。
- すべてを修復するわけではありません。「Cannot repair safely」（安全に修復できない）は想定された結果のひとつです。詳しくは[保守的な修復の範囲](../concepts/conservative-repair-scope.mdx)を参照してください。

:::note[検証の状況]
アプリが動作するのは Apple silicon（arm64）上の macOS 27 以降だけです。パッケージ化したアプリは、Apple A18 Pro（macOS 27.2）と Apple M4（macOS 27.0.1）で、ネイティブのパッケージングゲートと、実際の VoiceOver を使った確認を含むすべての対話的な受け入れ確認に合格しています。[検証状況](../develop/verification-status.mdx)を参照してください。
:::
