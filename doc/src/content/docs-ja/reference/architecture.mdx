## プロセスは 2 つでジョブは一度に 1 つ

アプリはネイティブの SwiftUI プログラムです（macOS 14 以上を想定し、必要な箇所では AppKit アダプターを使います）。ジオメトリの処理はすべて、短時間だけ動作する別の Python ヘルパープロセスで行われます。そのため UI の応答性が保たれ、エンジンがクラッシュやタイムアウトを起こしてもアプリが巻き込まれることはありません。

| 項目 | 方針 |
| --- | --- |
| ネイティブアプリ | SwiftUI。ファイルパネルとドロップ連携には AppKit アダプター |
| ジオメトリ | `engine/stl_doctor.py`（numpy、scipy、trimesh、shapely/GEOS を使用） |
| プロセス境界 | ジョブごとに 1 つのワーカープロセス。ジョブは逐次実行 |
| ワーカーの配布 | アーキテクチャに合わせて PyInstaller で固めた Python ヘルパーを、アプリバンドルに埋め込み |
| 配布形態 | Mac App Store 外で配布する単体アプリ |

アプリはヘルパーを自身のバンドル内（`Contents/Helpers/STLWorker.app/...`）から解決し、明示的な実行ファイル URL と引数配列で起動します（シェルは介しません）。環境変数は最小限で、`PATH=/usr/bin:/bin`、`LANG=en_US.UTF-8`、`PYTHONNOUSERSITE=1` のみを渡します。システムの Python は使いません。

## 責務の分担

**アプリ**は、ファイルのアクセス権限、取り込み時のスナップショット、ジョブの状態、プロセスのライフサイクル、ユーザーに見せるエラー、最終的な保存を担当します。**ワーカー**は、パース、完全な監査、保守的な修復、シリアライズ後のバイト列の検証、そしてジョブ専用のステージングディレクトリ内に候補 STL と詳細な JSON レポートを生成することを担当します。ワーカーは結果の保存先を決めることはなく、元のパスを上書きする権限を与えられることもありません。

## データの流れ

1. **スナップショット。** `SnapshotStore` がアプリ専有の非公開ルート（モード `0700`）を作成し、ドロップされたファイルをジョブごとのディレクトリに `input.stl`（モード `0400`）としてコピーします。元ファイルはローカルにある通常の `.stl` ファイルでなければなりません。エイリアス、シンボリックリンク、リモートのファイルは拒否され、ファイルサイズは 64 MiB までに制限されます。また、読み込み中に元ファイルが変更されていないことを再確認します。スナップショットの SHA-256 が記録されます。
2. **ワーカーの実行。** アプリは標準入力に JSON リクエストを 1 つ送り、標準出力から改行区切りの JSON イベントを読み取ります。[ワーカープロトコル](./worker-protocol.mdx)を参照してください。
3. **検証。** 結果を受け取ると、アプリはプロセスの終了ステータスを確認し、候補ファイルとレポートの成果物をそれぞれ宣言された SHA-256 とサイズで検証し、非公開の入力スナップショットが改変されていないことを確認します。
4. **確認。** 候補を伴う検証済みの `repaired` 結果だけが「Repair ready」になります。候補は保存されるか、クリアされるか、アプリが終了するまでステージングに残ります。保存していない結果は終了時に失われます。
5. **エクスポート。** ユーザーが保存すると、アプリのエクスポーターは候補を保存先ボリューム上の非公開のステージングフォルダにコピーし、バイト列を再検証したうえで、既存の名前をすべて拒否するアトミックなハードリンクで公開します。出力の名前は `<stem>-fixed.stl` で（以降 `-fixed-2`、`-fixed-3` と続きます）、名前の比較は大文字小文字を区別せずに行われます。レポートも同じ方法で `<stem>-report.json` としてエクスポートできます。

:::note
アプリが上書きを行うことはありません。これは CLI の `--overwrite` とは別の話で、アプリはこのオプションを公開していません。[CLI](../cli/index.mdx) を参照してください。
:::

## ジョブの状態

キューには次の状態が表示されます。Queued、Checking、Repairing、Verifying、No repair needed、Checked, review needed、Repair ready、Saving、Saved、Cannot repair safely、Check incomplete、Error、Canceled。それ以外は変更のないファイルに警告がある場合は「review needed」と表示され、失敗とは区別されます。

## 後片付けとプライバシー

キャンセルまたは失敗したジョブのステージングディレクトリは、ワーカーの終了を回収した時点で削除されます。クラッシュで残ったものは、所有権マーカー（ユーザー、UUID、デバイス、inode）とロックされていないリースによってアプリ所有であることが証明できる場合に限り、次回起動時に回収されます。モデルのバイト列はログに記録されず、テレメトリ、実行時のダウンロード、ネットワーク通信は一切ありません。

## macOS での未完了の確認

Swift のソースとエンジンアダプターは実装済みですが、macOS でのコンパイル、固めたヘルパー、署名、公証は別途検証します。[issue #1](https://github.com/Takazudo/zudo-stl-fix/issues/1) を参照してください。
