## 公開リリースは存在しません

成果物は `scripts/build-macos.sh` で作るローカルの開発ビルドだけです。アドホック署名のみで、Developer ID による署名はされておらず、公証もされておらず、配布もしていません。開発環境で起動できたからといって、ダウンロードしたコピーが Gatekeeper を通過する証拠にはなりません。

## 公開リリースに向けて残っている作業

Developer ID による公開向けの署名と公証は、別途承認が必要な作業です。リポジトリのスクリプトでは、認証情報を使った署名は一切有効になっていません。将来のリリースワークフローでは、次のことを行う必要があります。

1. 署名用 ID、Team ID、公証用プロファイルを非公開の設定として受け取る。
2. ネストされたコードを内側から順に、必要な Hardened Runtime の設定で署名し、最後に外側のアプリに署名する。
3. 公証し、ステープルする。
4. ダウンロードした生成物を Gatekeeper でテストし、ネストされた署名と初回起動を確認する。
5. 同梱する依存関係について、ライセンスとソース公開の義務を確認する。

:::warning
ユーザーに対して、quarantine 属性をまとめて削除する、Gatekeeper を無効にする、管理者権限でアプリをインストールする、といった指示は決してしないでください。
:::

リリースの検証はリリース用のワークフローで行うもので、そのワークフローは実際にリリースが求められたときにだけ追加します。日々のコミットでは、複数アーキテクチャの重いビルド、公証、完全なパッケージングは実行しません。
