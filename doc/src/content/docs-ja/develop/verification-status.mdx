## 概要

2026-11-08 時点で、サポート対象は **Apple silicon（arm64）上の macOS 27 以降だけ**です（オーナー判断。`docs/ACCEPTANCE.md` を参照）。パッケージ化したアプリは、2 台の arm64 の Mac でネイティブのパッケージングゲートと、実際の VoiceOver を使った確認を含む対話操作の受け入れマトリクス全体に合格しています。**macOS 27.2 の Apple A18 Pro** と **macOS 27.0.1 の Apple M4** です。ネイティブでの検証の先送りを管理していた [Issue #1](https://github.com/Takazudo/zudo-stl-fix/issues/1) はクローズされ、プラットフォームについて未完了の検証はありません。それより古い macOS と Intel x86_64 はサポート対象外のため、検証の対象でもありません。

証跡はリポジトリの [`verification/implementation/`](https://github.com/Takazudo/zudo-stl-fix/tree/main/verification/implementation) にあります。

:::warning
検証済みのメッシュであっても、印刷可能であること、寸法が合うこと、肉厚や強度が十分であることの証明にはなりません。以下のどの結果も「そのまま印刷できる」という意味ではありません。
:::

## 受け入れ確認の後に検証した修正

- 途中で切れたバイナリ STL は、途中で切れていることを示す理由とともに `invalid_input` の **Error** として報告されるようになりました（[Issue #30](https://github.com/Takazudo/zudo-stl-fix/issues/30)）。M4 での確認では誤解を招く理由とともに **Check incomplete** と表示されていましたが、その時点でも成功として扱われることはありませんでした。
- とても長い名前のファイルの修復結果を保存できるようになりました。保存先のファイルシステムが名前を保持できない場合は、ステムを短くします（[Issue #34](https://github.com/Takazudo/zudo-stl-fix/issues/34)）。[保存](../app-guide/saving.mdx)を参照してください。

どちらも macOS 27 上でネイティブに再確認済みです。

## 過去の経緯

以下は経緯として残している記録です。当時は macOS 14 が最低要件の案で、x86_64 も予定されていましたが、どちらも 2026-11-08 に対象から外しました。

### 2026-11-07 Apple A18 Pro macOS 27.2

2026-11-07 には 2 つのビルドがパッケージングゲートと幅広い Finder/UI の受け入れ確認に合格しました。確認した項目は、Finder からのドラッグ＆ドロップ、ファイルを開くパネル、ファイルごとの保存と一括保存、読み取り専用の保存先、キャンセル、終了、古いワークスペースの後片付け、ライト・ダークの外観、ウィンドウのリサイズです。このときに、失敗理由が表示されない問題と、**Choose Files…** のアクセシビリティ名の問題が見つかり、修正されました。

### 2026-10-16 macOS 26.6.2

2026-10-16 に、macOS 26.6.2、arm64、Xcode 27.0、Apple Swift 6.4、CPython 3.12.14 の環境で記録しました。

| `make test-worker` | 41 件成功 |

生成されたアーカイブはアドホック署名のみで、公証されておらず、リリースもされていません。

再配置したアプリで実施した対話的なチェックは次のとおりです。スペースと日本語を含むパスからの起動。`open -a` による 11 個の元ファイルすべての読み込み。ウィンドウが 1 つだけであること。健全な 9 個の元ファイルが **No repair needed**（修復不要）と表示され、欠陥のある 2 本のレールが **Repair ready**（修復準備完了）と表示され、微小三角形の警告が見えていること。保存のコントロールがその 2 つでのみ有効になること。未保存の修復があるときの終了確認。強制終了後の古いワークスペースの後片付け。フィクスチャのハッシュが変わっていないこと。

#### 見つかって修正された不具合

実際のアプリを動かしたことで、ユニットテストでは見逃されていた不具合が 2 つ見つかりました。ワーカーに渡る前に `/private` というパスの接頭辞が取り除かれていたため、すべてのファイルが失敗していたこと。そして、Finder から開いたファイルごとに新しいウィンドウが作られていたことです。どちらも修正済みで、テストでカバーされています。

#### 2026-10-16 時点で実施できなかった項目

セッションに UI を操作するためのアクセシビリティ権限がなかったため、当時は次の項目を実施していません。対話操作の項目はその後 macOS 27 の arm64 で合格しました。macOS 14 という最低要件と x86_64 は、確認する代わりにサポート対象から外しました。

- ウィンドウへの Finder からのドラッグ＆ドロップ。
- 保存パネル（ファイルごと・一括）と、保存した STL の独立した再検証。
- UI 上での読み取り専用の保存先と名前の衝突。
- UI 上での実行中・待機中のキャンセル。
- 詳細と JSON レポートの書き出し、および Reveal in Finder。
- キーボード操作、VoiceOver、ライトモードの外観、ウィンドウのリサイズ。
- macOS 14 という最低要件。実行時のテストは行っておらず、確認したのはホストの OS だけです。
- x86_64。

当時、保存、名前の衝突、権限、キャンセルのロジックは Swift のテストでのみカバーされていました。チェックリストの全体は `docs/ACCEPTANCE.md` にあります。
