## 概要

2026-11-08 時点で、パッケージ化したアプリはネイティブのパッケージングゲートと、実際の VoiceOver を使った確認を含む対話操作の受け入れマトリクスに合格しています。ただし対象は **macOS 27.2 の arm64 だけ**です。**macOS 14** と **Intel x86_64** は確認しておらず、[Issue #1](https://github.com/Takazudo/zudo-stl-fix/issues/1) で未完了のままです。作業全体はエピック [#22](https://github.com/Takazudo/zudo-stl-fix/issues/22) で管理しています。

:::warning
検証済みのメッシュであっても、印刷可能であること、寸法が合うこと、肉厚や強度が十分であることの証明にはなりません。以下のどの結果も「そのまま印刷できる」という意味ではありません。
:::

再配置したアプリで実施した対話的なチェックは次のとおりです。スペースと日本語を含むパスからの起動。`open -a` による 11 個の元ファイルすべての読み込み。ウィンドウが 1 つだけであること。健全な 9 個の元ファイルが **No repair needed**（修復不要）と表示され、欠陥のある 2 本のレールが **Repair ready**（修復準備完了）と表示され、微小三角形の警告が見えていること。保存のコントロールがその 2 つでのみ有効になること。未保存の修復があるときの終了確認。強制終了後の古いワークスペースの後片付け。フィクスチャのハッシュが変わっていないこと。

### 見つかって修正された不具合（2026-10-16）

実際のアプリを動かしたことで、ユニットテストでは見逃されていた不具合が 2 つ見つかりました。ワーカーに渡る前に `/private` というパスの接頭辞が取り除かれていたため、すべてのファイルが失敗していたこと。そして、Finder から開いたファイルごとに新しいウィンドウが作られていたことです。どちらも修正済みで、テストでカバーされています。

### 2026-10-16 時点の未完了項目（その後 arm64 で確認済み。macOS 14 と x86_64 を除く）

セッションに UI を操作するためのアクセシビリティ権限がなかったため、次の項目は実施していません。

- ウィンドウへの Finder からのドラッグ＆ドロップ。
- 保存パネル（ファイルごと・一括）と、保存した STL の独立した再検証。
- UI 上での読み取り専用の保存先と名前の衝突。
- UI 上での実行中・待機中のキャンセル。
- 詳細と JSON レポートの書き出し、および Reveal in Finder。
- キーボード操作、VoiceOver、ライトモードの外観、ウィンドウのリサイズ。
- macOS 14 という最低要件。実行時のテストは行っておらず、確認したのはホストの OS だけです。
- x86_64。

保存、名前の衝突、権限、キャンセルのロジックは Swift のテストでカバーされていますが、UI 操作によるテストは行っていません。チェックリストの全体は `docs/ACCEPTANCE.md` にあります。
