## ステータスラベル

各行には、次のラベルのうちどれか1つだけが表示されます。

| ラベル | 意味 |
|---|---|
| Queued | 先に追加されたファイルの処理が終わるのを待っています。 |
| Checking | ファイルを検証しています。 |
| Repairing | 対応している修復を適用しています。 |
| Verifying | 修復後のバイト列を再検証しています。 |
| No repair needed | チェックが完了し、実行すべき対応済みの修復も警告もありませんでした。 |
| Checked — review needed | 自動的な変更は行われていませんが、警告が残っています。保存できるものはありません。 |
| Repair ready | 修復結果が検証を通過し、ステージングしたバイト列も確認済みです。まだ保存はされていません。 |
| Saving | 検証済みの修復結果を、選択したフォルダに書き込んでいます。 |
| Saved | 選択したフォルダに検証済みの出力があります。 |
| Cannot repair safely | エンジンが保守的には解決しない欠陥がメッシュにあります。 |
| Check incomplete | サイズやペア数の上限、タイムアウトなどにより検証が中断されました。 |
| Error | ワーカーやプロトコルの問題など、動作上の失敗です。 |
| Canceled | ユーザーがジョブをキャンセルしました。 |

Queued、Checking、Repairing、Verifying は処理中の状態で、結果はまだ確定していません。保存が可能になるのは **Repair ready** のときだけです。

## 警告と失敗の違い

警告はステータスとは別に、行の下にオレンジ色の行として表示されます。そのため、一見正常に見える結果の陰に警告が隠れてしまうことはありません。

- **警告**があっても結果は止まりません。たとえば、微小三角形の警告が残ったまま修復が **Repair ready** になることも、正常なファイルが **Checked — review needed** になることもあります。警告の例としては、微小な三角形や、0 未満の Z 座標（配置に関する注意です。アプリがジオメトリを移動したり切り取ったりすることはありません）があります。
- **失敗**とは **Cannot repair safely**、**Check incomplete**、**Error**、**Canceled** のことです。出力は保存できません。また、タイムアウト、キャンセル、プロセスの失敗、リソース上限、完了しなかったスキャンが成功として報告されることは決してありません。

:::note
複数の独立したシェルがあること自体は欠陥とは見なされません。ただし、エンジンはそれらの包含関係や向きを保証せず、修復も行いません。
:::

## 受け付けられない入力

受け付けられないファイル（たとえば STL 以外の名前のファイル、エイリアス、シンボリックリンク、リモートファイル、64 MiB を超えるファイルなど）は、キューの上にあるオレンジ色のメッセージ領域に理由とともに一覧表示されます。**Dismiss** で消去できます。同じファイルを2回追加した場合は、すでにキューにあると報告されます。同じドロップに含まれるほかのファイルは、そのまま受け付けられます。
