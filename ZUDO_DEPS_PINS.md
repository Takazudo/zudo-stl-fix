# ZUDO_DEPS_PINS

Provenance for artifacts in this repository that were generated or adapted from
first-party (Takazudo / zudolab) upstreams rather than installed from the npm
registry. Registry packages are pinned in `doc/package.json` and
`doc/pnpm-lock.yaml`; this file covers the host-owned files the zudo-doc
generator wrote into `doc/`. Keep `pinned:` accurate on every sync.

- notes: Original scaffold commit 434c86f (2026-10-16) did not record the generator version. Its manifest (`@takazudo/zudo-doc ^7.0.0`, ZFB `4.5.2`) is consistent with create-zudo-doc 7.0.0, but that is unverified provenance. The 2026-11-06 reconciliation used zudo-doc-v7.0.0 (82049856397927077c5288465db34e44d0939260) as the old-upstream base; every file listed in `source:` except scaffold.ts/zfb-config-gen.ts is byte-identical between v7.0.0 and v9.1.4, so no host route/style/tsconfig change was needed. zfb-config-gen.ts changed: 9.x omits `themePack` for new projects and resolves an omitted value to Graphite, so `themePack: "default"` was added to keep Classic. Local customizations to preserve: (1) both doc route stubs add `REPO_SUBDIR = "doc/"` and pass `${REPO_SUBDIR}${contentDir}` as `docHistoryContentDir` (GitHub source paths are repo-root relative) and reword the docHistory header comment; (2) the locale stub keeps the DocHistoryBoundary binding plus per-locale `contentDir` / `isFallback` (fallback pages read EN history); (3) zfb.config.ts is hand-written (site name/description, six headerNav sections with `nav.*` translations EN/JA, header items, bodyFootUtilArea, assetViewer, `themePack: "default"`); (4) `check:links` uses linkinator and `check:html` uses html-validate (`doc/.htmlvalidate.json`) instead of the template's `scripts/check-links.js`; (5) favicons in doc/public are project-specific (green "S"), not the template's; (6) generator-written AGENTS.md / README / authoring-policy files are intentionally not adopted, because repository instructions belong to the native app. `.npmrc` still carries the template's `trust-policy-exclude[]=undici-types@6.21.0`; since @types/node 24 the graph has undici-types 7.24.6, which installed cleanly under `trust-policy=no-downgrade`, so the entry is inert but kept in step with the generator.
